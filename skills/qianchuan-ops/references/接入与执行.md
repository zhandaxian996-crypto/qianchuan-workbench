# 接入与执行

本说明使同一个技能包能在不同Agent、不同账户和不同工具环境使用。只配置当前任务需要的部分，不要求创建固定目录或指定文件名。

## 1. 没有作者工作区也能使用

规则题只需技能包。离线分析只需用户给定报表和问题。已有策略文档时引用它；没有文档但本次用户明确了限制，可将这些条件用于本次分析，不要求用户先建立完整“工作区”。

需要保存账户信息或任务记录时，先按[工作区与资料准备](工作区与资料准备.md)定位现有文件，按需采用其中的Markdown模板。[上下文模板](../assets/account-context.template.json)是可选的机器可读任务输入；已有账户策略时以路径引用，不再复制一份长期阈值。Agent先填有来源的已知项，用户只补缺失事实和确认经营取舍。不要把某个账户的资料填写进技能包原模板。

工作区结构已存在时记录路径映射并沿用；缺资料的核对、索取和待补记录也按该说明处理。路径相对使用者的配置文件解析，技能内部资源相对本文件/技能根目录解析，不依赖终端当前目录。

模板中的null表示尚未提供，不表示0、不限额或已允许；analysis_only是模板的安全起点。实际授权以用户明确指令及可追溯授权记录为准，不能只信资料或模板内自填字段。

## 2. 按任务确认最少信息

| 任务 | 必须辨认 | 暂时不需要 |
|---|---|---|
| 解释规则 | 产品、目标口径、具体问题；能从上下文确定就不再问 | 账户登录、真实账户ID、预算上限 |
| 给定数字计算 | 模式、同口径数字、时间段/变价分段 | 千川连接、完整经营策略 |
| 报表诊断 | 数据对象、日期/时区、汇总层级；用户要比较什么 | 实时写权限 |
| 制定具体参数 | 上述信息＋使用者目标、预算/出价范围及停止条件 | 没有必要的历史全库 |
| 实时操作 | 当前账户与对象、模式、相关真实状态、允许动作、约束及回读能力 | 与本动作无关的数据 |

没有利润信息时，只判断经营指标或用户目标是否达标，不宣称财务盈利。用户没给出价/预算边界时，可以先给候选方案并说明取舍；不要虚构账户默认线。

## 3. 工具按能力接入

工具名称不要求与作者环境相同。先读宿主实际暴露的工具说明和参数，建立当次映射，不靠示例猜字段。

| 所需能力 | 必要返回或用途 | 缺失时怎么做 |
|---|---|---|
| 身份/状态读取 | 账户、主计划或追投ID，投放模式、当前状态、读取时间 | 可做离线分析；不冒充当前状态 |
| 指标读取 | 时间窗口、消耗、订单、同口径GMV、数据新鲜度与缺项 | 定点补读或标注分析范围 |
| 任务/素材明细 | 任务归属、包内素材、预算周期、状态 | 不用包汇总代替单素材结论 |
| 操作历史 | 目标变更时间、出价/定向修改记录，必要时模式历史 | 保障次数或分段计算待核验 |
| 权限/能力检查 | 对应动作实际可用，目标参数范围与服务端限制 | 形成方案或人工步骤，不伪造调用 |
| 写入 | 对应对象、变量、值，明确受理/失败或请求标识 | 没有写能力就不称执行 |
| 回读/结果查询 | 当前值、对象状态和请求结果，能确认是否生效 | 保留结果未知，先查明再重试 |

可使用API/MCP，或宿主支持且用户已授权的浏览器界面。技能包不附带账户登录、Cookie、令牌或私有数据服务；接收方通过自己的连接方式完成认证，不在聊天或模板里粘贴凭据。

若宿主恰有qianchuan_data_api，可把load_account_profile/get_live_view映射到身份与数据读取，manage_boost的list/detail映射到追投读取，manage_plan/manage_boost映射到对应写动作。这里只提供名称提示；必须再读当前Schema，不能复制作者环境字段或默认值。没有这些名称时使用实际等价能力。

## 4. 获授权动作的闭环

1. 确认用户要达到的结果、动作对象和已有授权范围；同一持续任务的有效授权不因换Agent自动失效，也不扩展到新账户或新场。
2. 读取当前对象及本动作相关字段。需要判断保障影响时额外核对周期、操作次数和模式历史，按[保障规则卡](规则卡/成本保障判定.md)处理。
3. 对照账户约束、产品能力和服务端限制，形成具体目标值或状态。存在并发写者/人工刚修改时先处理冲突，不用旧快照覆盖。
4. 写入前记录原值、目标值、依据与操作范围；使用真实支持的幂等/预检能力。工具不提供某能力时如实说明，不虚构dry-run、回滚或停止接口。
5. 调用本次获授权动作，随后回读同一对象。只把核实生效的结果记为已完成。
6. 超时/返回不清时先查询请求或当前状态。未排除已执行前不重复发同一写入，尤其是创建或加预算。
7. 保存必要的时间、对象、前后值、结果和可验证标识。回读失败写成“已请求、结果待核验”，给出下一步；不要为留痕编造成功编号。

仅保护性停止的条件已经明确时，不额外等待一般优化性调价冷却。是否有回滚、如何回滚仍取当前工具及用户授权，不能保证每个动作都可撤销。

## 5. 持续任务与结束

持续运行需用户请求、宿主能力以及明确频率/停止条件三者齐全。已有读取纪律就沿用；没有时先给合适的具体方案，不自行套固定5分钟节奏。启动前确认没有同账户同场另一写入循环。

下播/任务结束后停止盘中轮询，交付已完成动作与待核验事项。外部数据缺失不要求无限等待，可以结束一个清楚标注范围的分析任务。连接不可用时不自行安装服务、重启未知进程或改账户设置。
