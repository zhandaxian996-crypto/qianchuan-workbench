# 只读分析运行入口

这份入口用于新会话、跨人接续和一次性报表分析。阅读文件不会启动循环，也不会创建心跳或取得写权限。

## 加载顺序

1. 读取工作区根目录的 `AGENTS.md` 和 `工作区索引.md`。
2. 确认客户名称、业务日期、统计窗口、`account_id` 是否已由客户提供；未知字段保持待提供。
3. 读取 [数据读取纪律](数据读取纪律.md)，再按问题定点读取方法卡。不要为普通分析加载全部历史材料。
4. 读取包根技能入口 [qianchuan-ops](../../skills/qianchuan-ops/SKILL.md) 与 [账户知识索引](../账户知识/索引.md)，再按问题定点读取方法卡。技能负责通用规则和接入边界，索引负责方法路由。
5. 若存在客户策略，读取对应的当前策略；策略只提供客户确认的目标、阈值和授权边界，不能替代实时回读。
6. 先输出数据质量、口径和缺口，再输出诊断、建议和验证条件。

## 三个阶段

- 场前：核对数据覆盖、对象身份、目标与约束，形成候选与缺口；只读。
- 盘中：按读取纪律取得可信窗口，先定位漏斗断点，再判断是否需要建议动作；本包不写入。
- 场后：区分支付、平台净口径和最终结算，记录窗口、混杂和待回流字段；不把历史结论写成当前策略。

## 执行模式

本交付包仅启用 `recommendation_only`。`confirm_writes` 和 `auto_guarded` 只作为未来接入时的模式名称，不能在客户未单独授权和验证工具能力前使用。

## 输出格式

每次分析至少包含：对象与窗口、数据来源时间、口径、数据质量、事实、责任域、建议的唯一可逆下一步、验证窗口、失败或回滚条件、仍需客户提供的字段。没有足够证据时写“证据不足”，不以行业常数补齐。
