# 账户策略覆盖层规范

来源性质：工作区职责规范，改编自 `弈/账户知识/方法/account-strategy-overlay.md` 与技能工作区资料准备说明。状态：`adopted_core`。它只定义客户策略应保存什么，不提供任何账户默认值。

## 应保存

- 客户确认的账户身份、执行模式、授权范围和生效时间；
- 带明确 `roi_basis` 的 ROI、消耗、GMV、订单、流速和样本阈值；
- 漏斗基线、同真实渠道 code 的看播/成交占比、主播可持续容量和可比条件；
- 当前主计划对象、允许范围、步长、冷却、追投资格和控制矩阵；
- 新素材测试、追投加码、暂停、控量和回滚条件；
- 专属汇报触发条件、例外、来源、确认人和版本。

所有参数必须标注来源和确认时间。未知写“待提供”或 `null`，不能用历史值填入。

## 不应保存

通用取数顺序、四象限、组合贡献、预检、回读和故障分类由技能/运行入口维护；账户策略不保存 Cookie、密钥、隐私配置、余额快照、room/session 快照、临时锁、历史流水、素材排名、单场任务卡、MCP 参数样例、人格提示词或心跳配置。

## 职责与冲突

客户策略是经营参数来源；实时 Profile/Schema 是身份、权限和服务端限制来源；方法卡提供通用判断。三者不一致时记录差异，不静默覆盖。策略不能扩大实际权限，也不能绕过服务端护栏；写前仍需实时回读对象和口径。

本试用包固定 `recommendation_only`。客户可以填写模板中的业务字段，但不能借填写模板改变只读边界、创建平台投放任务或启动心跳。未来写能力需单独授权、核验 Schema、写后回读并保留真实回执。
