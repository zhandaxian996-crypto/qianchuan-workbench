# 追投、预算与一键起量纪律

来源性质：工作区通用方法卡，改编自 `弈/账户知识/方法/boost-control.md`。状态：`adopted_core`；一键工具和实验均为 `experiment_only`，本包只读。

追投是独立的增量输入，必须与主计划分开归因。它可以放大同场已验证赢家，或在有界预算内验证明确假设，不能作为修复低 ROI、低流速或直播间承接的万能补丁。

## 1. 每轮拆分

逐条核对投放中、预算到顶、被动停和人工暂停对象，记录任务 ID、素材/直播间对象、状态、来源、窗口、增耗、增单、同口径 GMV/ROI、`roi_basis/settlement_window`、预算进度和剩余配额。还要检查重复追投、打包任务、主计划归因混杂，以及本轮是续跑、观察、加预算、调节、暂停候选还是不可判断。

追投总流速只能帮助定位对象。任务自身证据不足时不能因总流速高而收量；一个任务盈利也不能因为其他任务亏损而被连坐。

## 2. 创建前预检

1. 以当前 Schema 确认真实 action、参数、范围和返回契约。
2. 核验客户账户、场次、主计划、真实 `material_id` 或直播间对象。
3. 核验 Profile、权限、数据新鲜度、目标口径和客户策略资格。
4. 确认没有同对象活跃追投、打包重复或互斥任务。
5. 核对余额、配额、频率、冷却、剩余时长和并发记录。
6. 写清预算、窗口、成功条件、停止条件和回滚方式。
7. 同轮不同时修改主计划、素材和其他追投变量。

只有 ROI 目标动作才核验目标的 `roi_basis/settlement_window`；出价动作核验出价模式、单位和范围。接口返回 `roi_basis_required` 或 `roi_basis_mismatch` 时保留真实错误，不自行换算。效果 ROI 缺失只阻断依赖它的判断，不阻断查询或已经满足自身停止条件的只读建议。

## 3. 生命周期与失败处理

```text
候选 → 预检 → 单变量建议 → （未来获授权后执行）→ 回读状态与 operation_id
→ 观察单任务增耗/增单/净结果 → 续跑、加预算、调节或可逆暂停建议
```

创建返回 ID 不等于生效；未来执行时必须同时回读 effect_status、实际状态和消耗。没量先查状态、重复对象和冷却，再按策略提出单步释放；不能同时加预算和调 ROI。流速快且盈利时先看任务自身边际与预算，不因速度快自动收量。达到账户策略的加码条件才形成单次加预算建议，之后重新观察。达到停止线时形成可逆暂停建议；人工暂停、被动停或身份不明任务不能自动恢复。

支付、平台净成交、最终结算和乘方综合 ROI 不互换；口径冲突先阻断，不挑一个有利数字。

## 4. 新素材与探索

每个探索项必须写假设、素材角色、独立样本线、预算、窗口、成功/失败和退出条件。探索要有合理机会，但不能无限免责；结果写回素材角色和证据等级，不把单场偶然值固化为通用经验。赢家放大需要同口径结果、订单、跨窗口稳定和主计划归因清楚。

## 5. 直播间直投与短期工具

直播间直投先看承接、GPM、进房转化和净结果；承接弱时加量会放大问题。多商品场必须让增量与商品完整讲品周期、价格/福利释放对齐；至少覆盖一个完整周期再判断。

一键起量先核对工具是否支持停止或回退、持续时长、允许消耗、剩余时长和客户授权；不能把短期工具称为必然可逆。一键控量只作为预算约束，不自动改变主计划 ROI；创建前确认没有活动控量任务，提前停止能力以 Schema 和回读为准。当前包只输出建议，不创建、修改、暂停、删除或启动心跳。

## 6. 留痕

未来写操作的留痕要带对象、前值→后值、依据、回读状态、真实 `operation_id`、下一检查点、成功/失败和回滚条件。没有真实回执只能写待核验。品牌广告、云图、Feed/人群定向和乘方写操作当前标为 `blocked`，只能做解释或实验设计。
