# 直播经营漏斗诊断

来源性质：工作区通用方法卡，改编自 `弈/账户知识/方法/live-funnel-diagnosis.md`。状态：`adopted_core`；渠道归因和实验回切依赖当前接口与客户策略，证据不足时为 `blocked` 或 `experiment_only`。

## 1. 先验真

先确认账户、场次、窗口、`source_at`、`dataValid`、`partial/errors`、`roi_basis` 和 `settlement_window`。支付、平台净成交、最终结算和乘方综合口径分列；字段名如 `netGmv/netRoi` 不证明最终结算。关键字段陈旧、跨场、无效或未知时责任域先标为数据链路，不能用空值补 0。

## 2. 统一漏斗

```text
付费进入 → 停留 → 商品点击 → 支付 → 退款/结算
```

使用 `shows/views/product_clicks/pay_orders` 与 `show_to_watch/watch_to_click/watch_to_pay/click_to_pay`，同时保留窗口、来源时间、数据有效性和质量。显著性由客户策略样本线与可比基线决定，没有门槛就写证据不足。

| 断点 | 需要比较 | 首要核验 |
|---|---|---|
| 付费进入 | 展示、进入、进入率、计划/素材状态 | 曝光机会、预算/余额、审核、库存、挂车 |
| 停留 | 进入后停留、在线、GPM | 开场、画面、主播状态、承诺是否兑现 |
| 商品点击 | 看播到点击、主推品 | 商品呈现、卖点、福利和价格机制 |
| 支付 | 点击到支付、订单 | 券价、库存、规格、赠品、商品页、信任 |
| 退款/结算 | 支付、平台净、最终结算 | 承诺、品质、履约、售后和回流窗口 |

每个异常点同时核对主播、商品、价格/券/库存、话术、素材、计划和追投事件。时间不对齐或多个变量同窗变化时只给排查顺序，不抢因果。

## 3. 渠道与在线人数

渠道名只使用接口原样标识；分列 `watch_count`、`pay_count`、`pay_amount`、各自占比和效率。金额不能冒充人数；只有金额字段时人数与人数占比保留 `null`。同 code、同定义、同时间的基线才可比较，code 变化或基线缺失时降低置信度。占比变化但点击、支付、GPM 和 ROI 健康时先观察，不据此收量。

在线人数只有连续同定义快照才可用于趋势：在线、点击、订单、GMV、GPM 同步增长可能是健康扩量；在线涨而点击不涨指向停留/商品呈现；点击涨而支付不涨指向价格、库存、规格、信任或人群；消耗和在线涨而订单、GMV、GPM持续恶化才形成稀释候选。单个截面、间隔未知、跨场或口径变化时趋势不可用。

## 4. 六责任域

| 责任域 | 典型证据 | 首个经营动作 |
|---|---|---|
| 素材 | 进入端或内容漏斗异常，承诺与直播间不一致 | 修钩子、承诺或准备替补 |
| 主播承接 | 进入正常，停留、点击或 GPM 下降 | 恢复开场、讲品结构和节奏 |
| 商品与价格 | 点击或支付断点，券价库存异常 | 核对并恢复成交机制 |
| 投放计划 | 基础获量变化而漏斗稳定 | 核验目标、预算、余额、状态和冷却 |
| 追投 | 单任务增量或重复任务造成混杂 | 查任务明细、重复对象和边际 |
| 数据链路 | 陈旧、部分失败、身份/口径冲突 | 恢复可信数据；本轮只读 |

先给能修复断点的经营动作，再判断投放建议。主播、商品或数据问题不能用调 ROI 伪装解决。

## 5. 投放建议与多商品

定位断点后，局部素材才形成可逆候选；高 CTR 不自动追投，0 单不自动淘汰。多素材共同走弱且经营端正常时再查计划。边际盈利、基础流速欠饱和且主播有容量时，主计划释放与赢家追投二选一。`roi_basis=unknown`、口径冲突或元数据未知阻断 ROI 创建/修改。

多商品任务记录商品顺序、完整讲品周期、主播/价格机制和可比窗口。至少观察一个完整周期；成交锚点包含商品、人群、痛点、卖点、证据、话术、价格/券/赠品、节奏和催单。换品、主播、价格、券或追投同时发生时标记混杂。

## 6. 证据状态与汇报

`adopted_core` 适用于跨账户可观测方法；`reference_only` 只给排查方向；`experiment_only` 必须写假设、样本、成功/失败和退出；`case_only` 不迁移固定数字；`blocked` 表示接口不能观测或不支持。专项汇报固定包含漏斗断点、责任域/岗位、首个经营动作、投放建议或阻断原因、验证窗口、事件混杂、数据可信度、来源时间、样本、口径和缺口。
