# 抖音电商罗盘决策指南

罗盘用于店铺经营、退款和人群结构诊断，不替代盘中千川同口径边际，也不单独触发投放写操作。

## 读取原则

1. 通过当前 MCP 的 `get_compass_data` 读取，不直接操作浏览器、Cookie、CDP 或原始接口。
2. 明确时间窗口、更新时间和数据有效性；T+1 或历史数据不得冒充当前盘面。
3. 账户切换必须显式传入当前任务的 `account_id`，不得把另一个店铺的数据或阈值带入。
4. 聚合项、平台诊断和模型标签只作线索；支付、平台 1 小时净、最终结算和乘方综合口径分列，最终经营判断只使用已核验的 `roi_basis/settlement_window`。

## 什么时候读取

- 场前：校准客户约定历史窗口的退款、客群、商品和成交结构。
- 盘中：只有千川盘面无法解释异常，而且罗盘数据足够新鲜时，追加一次专项读取。
- 场后：解释退款回流、净客单价变化、商品结构和人群偏移。

普通分析不要反复读取罗盘全量数据；当前试用包不启动心跳。

## 核心观察维度

| 维度 | 用途 | 边界 |
|---|---|---|
| 支付、平台 1 小时净与最终结算 | 区分支付、短窗退款与最终收入 | 不混用不同 `roi_basis`，不把 1 小时净称为最终结算 |
| 退款金额、退款率和原因 | 判断利润被售后侵蚀的程度 | 阈值来自账户 Profile，不使用跨店固定值 |
| 新客/老客结构 | 判断获客结构变化 | 不能为亏损素材提供免死理由 |
| 商品与价格带 | 解释净客单价和转化变化 | 需要结合主播过款与投放窗口 |
| 人群画像与地域 | 支持内容和定向诊断 | 历史画像不是盘中实时因果 |

## 决策纪律

- 罗盘异常先形成“可能原因 + 需要补充的当前证据”，不得直接声称因果闭环。
- 退款高、同口径 ROI 低时，先区分商品/售后、直播间承接和素材流量责任域。
- 任何计划、追投或素材动作仍须回到当前千川盘面，验证场次、真实边际、对象状态、权限和冷却。
- 所有账户数值只从已确认 Profile 或当前 MCP 返回读取。

## 字段核验补充

读取指标目录和字段说明，按 `index_name` 定位，不依赖数组序号。比例字段先核对 `unit`，人数占比、金额占比和复购率不能混用；真实零可以有效，缺失或失败保留未知。

成交老粉占比不能直接当作老客复购率或老粉销售额占比。店铺绑定账户消耗与店铺被投消耗可能覆盖不同归属；未核对定义和范围时，不当作当前单直播间消耗。接口未提供的字段明确列为缺口。

本版保留经营诊断方法和字段检查，不携带开发阶段的实抓请求、直播间标识、观测数值、响应文件或原机器路径。当前能力以工具 Schema 和真实返回为准，不能把历史浏览器抓取经历说成客户已接入。
