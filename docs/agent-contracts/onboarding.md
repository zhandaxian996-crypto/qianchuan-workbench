# 新用户接入与配置

打开本机工作台 `/v4`。无账户时自动进入“接入与配置”；已有账户可继续配置或新增账户。没有历史数据、不了解 ROI，都可以先完成只读接入。

## 用户实际需要做什么

1. 点击“打开千川登录”，在自己的浏览器完成登录。
2. 使用页面链接的 Cookie Editor 导出 JSON 文件，在工作台选择这个文件。不要把 Cookie 粘贴到对话里。
3. 确认系统识别出的账户。多个主计划会列出供选择，不按排序默认取第一条。
4. 分组回答目标、财务口径、预算、操作范围和通知偏好。不知道就留空；每组提交后可退出，下次继续。
5. 核对预览，勾选确认，执行只读预演并保存。页面显示“只读接入已完成”后，Agent 可以读账户配置和盘面。

目前新向导只开通只读。选择 `confirm_writes` 或 `auto_guarded` 只保存授权意向，返回 `budget_and_test_loss_enforcement_not_ready`：日预算、场预算、测试损耗尚没有贯穿全部写入口的强制执行链路。不能据此向用户承诺自动投放已启用。仅刷新已有账户的 Cookie 不改变原授权；明确确认保存向导会把该账户切为只读，不改变其他账户。

## 共用入口

CLI 保留 `npm run setup`。HTTP、CLI、MCP 都调用 `accountOnboarding` 的问题定义、验证和保存逻辑；没有另建后端，也不要求新用户安装 n8n 或 Cookie 中转服务。

| 入口 | 能力 |
|---|---|
| `GET /api/onboarding` | 首次状态、已有账户、Cookie 获取入口、官方手册可用性 |
| `GET /api/onboarding?account_id=…` | 当前答案、缺口、下一组问题、草稿版本、平台观测、授权与只读预演结果 |
| `POST /api/onboarding` | `import`、`select`、`draft`、`rehearse`、`save` |
| MCP `setup_account` | `status`、`draft`、`rehearse`、`save`；不接收 Cookie 或文件路径 |
| `npm run setup` | 文件导入、账户选择、分组问答、只读预演和确认保存 |

HTTP 接入仅限本机同源访问；POST 必须是 JSON 且携带 `x-qc-onboarding: 1`。网页和 MCP 已处理此请求头，普通用户不用填写。

Agent 初次连接没有账户时，业务工具返回 `account_setup_required` 和本机接入地址。调用 `setup_account status` 后按 `next_questions` 每次只问一个必要问题，复用 `revision` 保存草稿。不让用户写启动提示词；不重复索要已有答案；不把“请求的授权”说成“已生效权限”。

## 数据边界

- `platform_current` 是已核验计划的当前 ROI/出价、预算与口径；不是经营目标。
- `answers.target_roi` 与 `operating.roi_basis` 是用户经营目标；保本线单独保存为 `break_even_roi`、`break_even_roi_basis`。
- 未知数值保留 `null`，有效零预算保留 `0`。没有历史时不生成流速容量或素材推荐。
- 平台列表、余额、直播状态分别有读取时间和有效性；直播状态缺失是 `null`，不是下播。当前只有计划状态，尚未把全部追投和短期工具状态纳入接入预演。
- 首次账户身份只读验证必须成功；主计划缺失或冲突可先只读保存，但不能宣称主计划已核验。
- 预演十分钟后、草稿被修改或 Cookie 已变化，保存前需要重新预演。多入口版本冲突返回 `409`，不覆盖后来者的数据。

## 保存与恢复

默认以 `server-app` 为配置根目录；便携部署用现有 `QC_RUNTIME_CONFIG_ROOT` 指定其他目录，不依赖开发者电脑路径。

| 文件 | 内容 |
|---|---|
| `config.json` | 账户注册、独立 Cookie 文件名、账户级执行限制 |
| `account-profiles/<id>.json` | 经营目标、预算、授权意向、来源、用户确认时间、能力缺口 |
| `onboarding/<id>.json` | 分步草稿、版本、只读预演与观测；不存 Cookie 正文 |
| `scripts/qianchuan_cookie_<id>.txt` | 兼容现有读取模块的 Cookie header，只保存在本机 |

Cookie、配置和 Profile 使用同一恢复事务写入。失败恢复旧文件；进程崩溃后下次读取配置前恢复未完成事务。跨入口保存会检查文件版本。事务恢复文件可能包含之前的凭据，和 Cookie 一样属于私密运行资料，不能公开或提交。

Cookie 导出必须来自千川域；其他网站条目忽略。格式错误、过期登录项、账户不符、同名不同值或无法安全转换的路径 Cookie 会明确拒绝，不试着猜。在线验证只发读请求，不测试真实投放。

## Skill 与发布边界

`qianchuan-ops` 继续只核验官方规则，本次没有加入账户阈值或初始化流程。项目入口负责自动引导；配置保存答案；Agent 判断；服务端约束与执行。官方资料先查 `QC_OFFICIAL_SKILL_DIR`，再查当前用户的 `.agents/.hanako/.codex/skills/qianchuan-ops`，找不到就标缺失。

本次不是完整商业化安装包：未部署、未重启、未启用客户自动投放。分发前必须排除真实配置、Cookie、Profile、草稿、恢复事务、历史库与抓包；`.gitignore` 不会自动移除已经跟踪的自用档案。

## 接入后的账户校准

接入完成不等于经营参数已校准。保留原有只读校准流程，但不把它设为新用户首次使用的门槛：

- 用当前 `load_account_profile` 与盘面核对身份、场次、主计划、数据时间和各 ROI 口径；冲突时列出来源，不自行选值。
- 按需读取最近 7～14 天可比数据，整理基础/追投/总流速容量、经营漏斗与渠道基线、样本门槛、时段和场次时长、素材与追投结构。每项带来源、更新时间、样本和缺口；漏斗转化率按 `0..100` 保存，`12.5` 表示 `12.5%`。未知渠道不猜标签。
- 主播、商品、价格机制、时段等可比条件须记录。财务保本线来自用户确认的成本口径，不能用历史 ROI 代替；无法校准的字段继续缺失。
- 向用户确认经营与财务边界、受保护对象、禁止恢复对象及执行授权。至少完成一场只读观察，核验累计、边际与直播起止后，才考虑将校准状态改为 `confirmed`；向导本身不自动执行这一步。
- 旧 `settlement_net` 迁移为 `platform_net_1h` 并保留迁移说明，不解释为最终结算。旧 Profile 缺少基线时可以读取，降低判断置信度，不填入虚构阈值。
- 商品、主计划、主播、时段或口径显著变化时重新校准。账户规则不写入官方 Skill，也不复制给其他账户。

将来补齐全部预算硬限制并验证后，再按用户确认逐级开放操作。当前新向导没有授权激活入口；`confirmed` 校准状态也不能绕过这个限制。
