# 有效投放：接口映射与状态解释

本页属于 `qianchuan-api` 技术契约，说明平台返回值如何映射为机器字段。官方规则内容需用 `qianchuan-ops` 的原文快照核验；账户是否调整由当前账户策略决定。普通 5 分钟盯盘不加载。

## 1. 四个值必须分开

| 字段 | 含义 | 能否直接用于经营动作 |
|---|---|---|
| 当前计划目标 | 主计划当前设置的目标值 | 仅在口径、对象和权限核验后作为计划参数 |
| 当日有效投放加权目标 | 千川按当天基础计划各时段净成交金额与对应目标计算的完成度值 | 否；不是实际经营 ROI |
| 平台推荐上限 | 千川按账户历史、实际达成与当日竞争给出的每日参考 | 只能作拿量旁证 |
| 实际经营 ROI | 支付、平台1h净、最终结算或乘方综合结果 | 与同口径经营阈值比较 |

不得把这四个值简写成同一个“ROI”。

## 2. 三要素

平台将以下三项同时满足定义为当天有效投放：

1. 当日有效投放净成交 ROI 目标不高于系统建议；
2. 日直播全域推广消耗至少 200 元；
3. 投放时长至少覆盖当天直播时长的 50%。

系统无建议值时，任意目标按平台规则判为采纳。计划列表展示当日实时状态，有效投放日历展示近90天结果。

## 3. 加权目标公式与排除项

```text
effective_goal = 当日基础计划净成交金额总和
                 ÷ Σ(各时段净成交金额 ÷ 各时段净成交ROI目标)
```

- 只统计全域基础计划；
- 排除一键起量、视频追投等调控工具；
- 排除乘方投放期间；
- 当前计划设置变化后，加权目标不会简单等于最后一次设置值。

该字段建议命名 `effective_delivery.weighted_roi_goal`，不要扩展为新的实际结果 `roi_basis`。

## 4. 调用方边界

- 有效投放达成不代表盈利；未达成也不等于业务故障或处罚。
- 推荐值越低通常越容易拿量，但接口不得据此自动生成写操作。调用方结合账户保本线、主播承接容量、真实边际、剩余时长和当前授权决定。
- 不为满足标签而盲目降 ROI；若拿量增加但点击、订单、GMV或GPM不同步，按扩量稀释流程处理。
- 平台返回状态原样保存，带 `source_at/dataValid/date`；本地可做解释和验证，但不覆盖平台值。
- 消耗与时长按计划维度统计，全域与乘方净成交ROI出价均纳入。调控工具消耗是否计入“投够消耗”在当前证据中未明确，接口未拆分时保持 `unknown`。

## 5. 推荐结构

```json
{
  "effective_delivery": {
    "date": "YYYY-MM-DD",
    "achieved": false,
    "roi_goal": {
      "achieved": false,
      "weighted_value": 2.83,
      "recommended_max": 2.73,
      "recommendation_available": true
    },
    "spend": { "achieved": true, "value": 968.63, "required": 200 },
    "duration": { "achieved": true, "coverage_percent": 100, "required_percent": 50 },
    "source": "qianchuan",
    "source_at": null,
    "dataValid": true
  }
}
```

示例数字只展示字段关系，不作为其他账户或其他日期的默认值。
